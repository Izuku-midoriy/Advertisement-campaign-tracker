# Week 13 — Fixed Configuration Management Deliverables

Run commands from the project root, where `Week_13_Configuration_Management_Deliverables` is a child folder.

1. Rebuild the runner (the Dockerfile now verifies that the CLI exists):
   ```powershell
   docker build --no-cache -t adtracker-ansible-runner -f Week_13_Configuration_Management_Deliverables/ansible/Dockerfile .
   ```
2. Confirm Docker CLI inside the runner:
   ```powershell
   docker run --rm adtracker-ansible-runner sh -c "command -v docker && docker --version"
   ```
3. Capture the actual first run:
   ```powershell
   New-Item -ItemType Directory -Force .\Week_13_Configuration_Management_Deliverables\evidence | Out-Null
   docker run --rm `
     -v "${PWD}:/workspace" `
     -v /var/run/docker.sock:/var/run/docker.sock `
     -w /workspace `
     adtracker-ansible-runner `
     ansible-playbook `
     -i Week_13_Configuration_Management_Deliverables/ansible/inventory.ini `
     Week_13_Configuration_Management_Deliverables/ansible/playbook.yml 2>&1 |
     Tee-Object -FilePath Week_13_Configuration_Management_Deliverables/evidence/ansible-run-1.txt
4. Check `curl.exe -i http://localhost:8081/actuator/health`.
5. Repeat the playbook command and save as `ansible-run-2.txt` to check idempotency.

The log must be generated by the real environment. This package intentionally contains no fabricated execution log. It does not remove/reset database volumes or recreate containers.
